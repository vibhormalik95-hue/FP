# Shared implementation contract

This contract describes the finished Experiment 1 implementation. The separate Experiment 2 schema, backends and gates are specified in docs/experiment2-protocol.md.

Project root is this directory. Python package `feedctrl`. Use Python 3.11+ and standard library where practical. Root coordinates integration. Do not overwrite another agent's files.

## Dataset
`data/processed.json` is an object with `metadata`, `items`, `users`. Items: list of `{item_id: int, categories: [str]}`. Category strings are honest opaque IDs such as `category_12`, unless an official human-readable mapping is verified. Users: list of `{user_id: int, train: [int], request_history: [int], test: [int]}` in temporal order. Global chronological boundaries prevent future interactions of other users entering training. Request construction may use train and request_history but MUST NOT use test. Train has >=3 items, request_history >=2, test >=1. Keep metadata of source, SHA256, split boundaries and inclusion filters. The schema can represent repeats, but the retained cohort has no repeated training items and no test/history item overlap. The frozen candidate policy still permits seen-item recommendations.

## Ranking
`feedctrl.model.train_model(data, output_dir, seed=42, epochs=3, **kwargs)` returns metadata and writes model files. `load_model(output_dir)` returns a predictor with `score(history: list[int], item_ids: list[int]) -> list[float]`. Model owner may add CLI. Candidate set is the full dataset item list; permit seen-item recommendations consistently (a frozen design choice, not justified by repeated targets in the retained cohort); no held-out input enters scoring. Freeze model across A-E within each seed.

## Controls
`feedctrl.controls.parse_control(text, categories, backend='rule', **kwargs)` returns dict `{operation: 'boost'|'mute'|'reset'|'clarify', category: str|null, strength: float, source: str}`. Rule is a transparent diagnostic comparator, never an LLM substitute. Ollama backend fails explicitly on operational failure. `rerank(item_ids, scores, item_categories, command, profile=None)` returns ordered IDs. `item_categories` is dict[int,list[str]], profile is dict[str,float]. Hard mute removes matching items; no padding with forbidden items. Deterministic tie by item ID. Explain rankings by verified signals, no causal claims. Default score-normalized boost strength 0.25; profile applies same policy when identical intent to avoid confounding. Request set contains positive and negative category requests generated without test.

## Evaluation
`feedctrl.evaluation.run_evaluation(data, model, output_dir, parser_backend='rule', **kwargs)`. Returns summary and writes request-level CSV and JSON provenance. Conditions A item-feedback proxy, B A plus cached explanations (rank invariant), C free text, D profile, E C+D+B. A uses one representative historical item in requested category with explicit item-only feedback; absent exemplars are skipped consistently. B must equal A. E merging rules must prevent double counting. Clarify and operational failures counted/reported; do not silently convert unavailable LLM to successful rule run. Report both diagnostic and actual LLM separately. Unit is user, paired cluster bootstrap / signed-rank on user-aggregated metrics; no treating requests/seeds as independent users. TCP@10 positive target inclusion; TCER@10 negative target inclusion, explicit denominator and fill rate. HR@1 held-out relevance: the original absolute0.10 reading is archived. Current interpretation in results/audit_revision/analysis-v1.json reports both absolute0.10 and relative0.10 times the paired A baseline. The former passes numerically but permits complete baseline loss; the latter fails. Neither establishes useful quality preservation. Category requests are synthetic proxy controls, not human intent.

## App
FastAPI `feedctrl.api:app`; React in `web/`. App loads configured real data/model if present, otherwise prominently labeled deterministic fixture mode. API categories/users/feed/control/profile/reset/status endpoints. Per-session/user isolation and bounded inputs, no test labels exposed. Built-in rule mode default for demo; actual Ollama mode selectable with errors visible. UI must label opaque categories and fixture/data/backend status. No real video assets available: honest metadata cards, not a video playback claim.
